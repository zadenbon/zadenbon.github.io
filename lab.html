01 / Graphics, canvas · Interactive

Dynamic lighting and shadows

Move your mouse over the scene. The light follows it and casts real shadows from the obstacles in its path. Leave the scene and it drifts on its own.

A flat glow is a gradient. A real light has to work out which edges of each obstacle face it, extend those edges away from itself, and darken everything behind that line. That's what's actually happening here, recalculated every frame, not a pre-baked effect.

Obstacles: 4 · Mode: following mouse

Move over the canvas to steer the light

ctx.fillRect(0, 0, w, h);
shipped

const shadow = projectAway(light, edge, 1000);
ctx.fill(shadowPath(shadow));
02 / Layout · Interactive

Reflow: table vs. grid

Same three cards, two ways to lay them out. Drag the frame narrower and watch what happens to each.

A table forces fixed columns, so it either overflows or crushes its own content at small widths. Grid renegotiates the columns itself, no media query written for every screen size that exists.

Frame width: 340px · Overflowing: no

Drag the handle on the right edge of the frame

naive
<table>
  <tr>
    <td>Card</td>
    <td>Card</td>
    <td>Card</td>
  </tr>
</table>
shipped
.cards {
  display: grid;
  grid-template-columns:
    repeat(auto-fit, minmax(100px, 1fr));
  gap: 8px;
}
03 / Rendering · Interactive

Repaint cost: position vs. transform

Same dots, same movement, same bounce logic. The only difference is which CSS property moves them.

Changing top and left makes the browser recalculate layout for every affected element, every frame. Transform skips layout and hands the job straight to the compositor, which is why some pages feel choppy the moment there's more than a handful of moving parts.

FPS: 60 · Dots: 200 · Mode: shipped
naive
el.style.top = y + 'px';
el.style.left = x + 'px';
shipped
el.style.transform =
  `translate(${x}px, ${y}px)`;
04 / Algorithms, canvas · Interactive

Collision at scale

The same moving dots, checked for overlap two different ways. Push the count up and watch the gap widen.

Checking every dot against every other dot costs n squared comparisons. Sorting dots into a grid first means each one only checks its own cell and the eight around it, so the work grows with the scene instead of exploding with it.

Checks this frame: 0 · Naive would run: 0 · Mode: spatial hash
naive
for (let i = 0; i < n; i++) {
  for (let j = i + 1; j < n; j++) {
    checkPair(points[i], points[j]);
  }
}
shipped
const grid = bucket(points, cellSize);
for (const p of points) {
  for (const q of neighborsOf(p, grid)) {
    checkPair(p, q);
  }
}
05 / Events · Interactive

Debounce

Type in the box. Every mode sends a simulated request, watch how many actually fire.

A search box wired to fire on every keystroke sends a request per letter typed. Waiting for a short pause first turns twelve requests into one, without the person typing noticing any delay.

Requests fired: 0 · Mode: debounced
naive
input.addEventListener('input', () =>
  sendRequest(input.value)
);
shipped
function debounce(fn, ms) {
  let t;
  return (...a) => {
    clearTimeout(t);
    t = setTimeout(() => fn(...a), ms);
  };
}
06 / Loading · Interactive

Lazy loading

Scroll the strip sideways. Watch how many blocks load and when.

Loading every image up front spends bandwidth on content nobody has scrolled to yet. An observer that watches the viewport loads things right as they're about to matter, not a moment before.

Loaded: 0/16 · Mode: lazy
naive
blocks.forEach(b => load(b));
shipped
const io = new IntersectionObserver(es => {
  es.forEach(e => {
    if (e.isIntersecting) {
      load(e.target);
      io.unobserve(e.target);
    }
  });
});
blocks.forEach(b => io.observe(b));
07 / Accessibility · Interactive

Validation and keyboard reach

Two small checks that decide whether a page actually works for everyone, not just a mouse and a sighted user.

A silent form makes a person guess what's wrong. A div with a click handler is invisible to a keyboard. Both are easy to miss in a demo and both show up immediately in real use.

Live validation

Mode: live and accessible
naive
form.addEventListener('submit', e => {
  e.preventDefault();
  if (!isValidEmail(email.value)) return;
});
shipped
email.addEventListener('input', () => {
  errorEl.textContent = isValidEmail(email.value)
    ? ''
    : 'Enter a valid email';
});
